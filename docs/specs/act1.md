## Problem Statement

现在的可玩内容只是 Slice 0：五个房间、一个 173、一道门。它能证明"俯视 + 黑暗 + 凝视"这套机制立得住，但证明不了**幕 I 作为一段 30 分钟的体验成不成立**——玩家从测试室醒来、学会四种资源、走到检查点、坐进电梯的那整条路，目前有一半是空的。

具体缺口：走廊没有"纯黑省电"的压迫段；没有 SCP-294 这种资源赌博；没有 106 的预兆（腐蚀痕迹与远处拖拽声）；文档只有一份，撑不起"读东西"这个行为；存档只有一个终端且没有反馈；幕 I 的终点（电梯转场）完全不存在。

## Solution

把 `levels/act1.json` 扩成**完整的一幕 I**（约 30 分钟、10 个 beat），并按 `docs/design/game-design.md` 的第 5 节 beat 表落地。完成后玩家能从"173 测试室醒来"一路玩到"电梯停电、爬检修口"，中途经历两次呼吸点、读到六份文档、被 106 的痕迹吓到两次。

同时补一条**可自动化的验证缝**：一个 headless 场景运行器，让"这一段能不能走通"不再只能靠人肉试玩。

## User Stories

1. 作为玩家，我想在断电后的测试室里醒来时立刻明白"这里出事了"，这样我不需要读教程就知道要跑。
2. 作为玩家，我想在走廊里第一次看见 173 并自己发现"照住它 = 安全"，这样这个规则是我发现的，而不是被告诉的。
3. 作为玩家，我想在第一次强制眨眼时被它吓到，这样我会记住"眼睛也是资源"。
4. 作为玩家，我想在更衣室的白大褂尸体上找到 1 级门禁卡，这样我学会"卡在身上，不在桌上"。
5. 作为玩家，我想刷卡开门时听到读卡器的反馈声与广播，这样我知道自己刚刚被系统记录了一次。
6. 作为玩家，我想走过一段一盏灯都没有的长走廊，这样我必须学会关手电省电。
7. 作为玩家，我想在茶水间遇到 SCP-294，喝到一杯随机的、有时有用有时有害的东西，这样资源可以赌。
8. 作为玩家，我想在断电区第一次看见墙上的腐蚀痕迹，这样我在真正遇到 106 之前就开始害怕。
9. 作为玩家，我想在检查点终端存档并得到明确反馈，这样我知道死亡不会让我回到起点。
10. 作为玩家，我想在检查点读到事故记录，这样我开始把"谁放的 106"这条线拼起来。
11. 作为玩家，我想在电梯里经历停电、卡住、并从检修口爬出去，这样幕 I 有一个像样的收尾。
12. 作为玩家，我想在读文档时游戏世界暂停但氛围继续（底噪、心跳），这样阅读不破坏沉浸。
13. 作为玩家，我想在死亡后 2.4 秒回到最近存档点而不是重开整局，这样失败是可承受的。
14. 作为玩家，我想在 HUD 上只看得到眨眼、手电、体力三个资源，这样我不会被信息淹没。
15. 作为开发者，我想用一条命令验证整段关卡的数据合法性与连通性，这样我加内容时不会悄悄弄坏别处。
16. 作为开发者，我想用一条命令跑一个脚本化流程并得到 PASS/FAIL，这样回归不需要人肉试玩。
17. 作为开发者，我想让"文档"成为数据而不是硬编码字符串，这样加文档 = 加一条 JSON。
18. 作为开发者，我想让关键文档在拾取时打标记，这样第五结局的判定有据可依。
19. 作为本地化维护者，我想所有新文案都走词条表，这样中英切换不会漏。
20. 作为关卡设计者，我想在数据里标注"呼吸点"和"预期时长"，这样节奏调优可以量化。

## Implementation Decisions

- **关卡数据扩展**：`areas` 增加可选的 `floor`（地板材质变体）与 `zone`（分区标签）；新增顶层 `decals`（血迹/腐蚀痕迹/裂缝，带 z 与透明度）与 `documents`（id、标题键、正文键、是否关键）。加内容只改数据，不改代码。
- **文档即数据**：文档从"关卡里的一个交互物"升级为带 id 的实体，正文走 `i18n.gd`；拾取时写入 `docs_found` 集合，关键文档（第五结局用）用 `critical: true` 标记。
- **SCP-294**：一个新的交互类型（自动售货机），不引入通用"机器"抽象——它是唯一一台。四种结果：回复体力、回复手电、什么也没有、扣体力。结果用 HUD 提示与音效表达，不做数值面板。
- **触发器动作化**：现有 `triggers` 只有 `kind`（硬编码行为）。改为 `actions` 数组（`say` / `objective` / `fade` / `teleport` / `sound` / `activate_scp` / `end_act`），这样加一个 beat 不需要改 `main.gd`。
- **幕转场**：电梯是一个触发器，触发后播放黑场 + 一段文字 + 把玩家送到幕 II 的占位入口（本里程碑只到"黑场 + 幕 II 待续"卡片）。
- **106 预兆层**：只做环境层——腐蚀痕迹贴花、远处拖拽声、一次灯全灭事件。**不实现 106 的追踪 AI**（属于 M2）。
- **验证缝**：新增 `--scenario=<name>`，在 headless 下按脚本执行"传送到 A → 交互 → 断言状态"，输出 PASS/FAIL 并以退出码表达结果。它是本项目唯一的自动化测试缝，优先扩展它而不是新开一套。
- **不改的东西**：不做战斗、不做血量、不做成长；"看见"的判定不变（光锥 ∧ 睁眼 ∧ 无遮挡）。

## Testing Decisions

- 好的测试只断言**外部可观察行为**：玩家能否从出生点走到出口、进了电梯之后场景是否切换、拾取文档后 `docs_found` 是否包含它、体力耗尽后是否还能冲刺。不断言内部字段名或节点结构。
- 测试挂在**唯一的缝**上：`--headless -- --scenario=<name>`。现有 `--validate` / `--selftest` / `--audit` 三个开关就是这个缝的前身，继续在同一处扩展。
- 会有场景脚本：`act1_walkthrough`（从出生点到电梯，沿途拾取并触发所有 beat）、`act1_docs`（六份文档全部可拾取且可读）、`act1_death_respawn`（死亡后回到最后一个存档终端）。
- 每个 ticket 自带至少一条断言；没有可断言行为的 ticket 说明切片不够垂直。

## Out of Scope

- 幕 II 及之后的所有内容。
- SCP-106 的完整追踪与口袋空间。
- 幕 IV 回程与设施状态改写层。
- 第五结局的结算页（本里程碑只把标记打上）。
- 关卡可视化编辑器（M2 前再做）。
- 商业化、导出配置、Steam 页面。

## Further Notes

- 幕 I 的目标时长 25–35 分钟；每个 beat 在数据里标注 `expected_seconds`，用于事后量化节奏。
- 呼吸点硬性要求：每 6–8 分钟一次。幕 I 的两次呼吸点是更衣室与检查点。
- 所有新文案必须同时写中英两条；中文默认。
