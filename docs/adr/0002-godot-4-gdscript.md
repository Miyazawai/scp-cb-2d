# ADR 0002：Godot 4 + GDScript 作为引擎

- 日期：2026-10-22
- 状态：已接受

## 背景

本机在项目开始时不具备任何游戏引擎（无 Godot / Unity / GameMaker / Unreal），可用的是 Python 3.11、Node 24、.NET、Rust。

本项目 80% 的技术难点不在"画一个俯视游戏"，而在四件事：黑暗中的动态光照与遮挡、看不见的实体仍在按规则行动、走廊网络里的寻路 AI、用声音传递位置信息。

## 决策

使用 **Godot 4（GDScript）**，Windows 桌面为第一目标平台；Godot 的 Web 导出保留为后续的 itch.io 在线版本选项。

## 理由

- `Light2D` + `LightOccluder2D` + `TileMapLayer` + `NavigationRegion2D` + 音频总线，正好覆盖上面四个难点，都属于引擎一等公民。
- 场景与资源是文本格式，多个子代理可以并行修改不同文件而不产生二进制冲突——这在本项目的开发方式里是硬性要求。
- 备选方案的代价：PixiJS/Phaser 需要自己写光照与遮挡的 WebGL shader（等于先重造半个引擎，再谈做游戏）；pygame 同上且发布链路更差；Rust + bevy 的编译等待会让"改—跑—看"的迭代循环变慢，而本项目严重依赖快速迭代。
- 唯一让 B（TypeScript）更有吸引力的情形是工期短于 4 个月，本项目的体量排除了这一情形。

## 后果

- 团队需要熟悉 GDScript 与 Godot 的节点/场景范式；工程结构由引擎规定，不能随意组织目录。
- 引擎版本升级需要谨慎（4.x 内部仍有破坏性改动），锁定一个次版本直到内容完成。
- 编辑器与导出模板需要下载（约 110MB + 约 1GB 导出模板），首次运行成本高于纯代码方案。
