# 程序化像素素材可行性探针 / SCP Facility

## 结论先行

1. **能用的部分：地面/墙面/格栅/门框/读卡器/通风口/管道/灯具这类“材料与图标”已经达到可用的原型占位水平。** 16 色限制、硬边、4 倍最近邻检查都成立；在 4x 下能读出是什么，也能拼进房间。
2. **不能用的部分：角色与动画、光照。** 4 方向 2 帧角色只能算“能看懂大概朝向的占位小人”，轮廓、脸、肢体分离和步行动作都明显低于商业角色素材；场景光只是后处理的 dither，不是可复用的光照方案。
3. **它看起来更像“程序员像素画（programmer art）”，不是“手绘像素画”，也不是常见的 AI 塑料感。** 调色板是这套东西里最像人做的部分；重复的 16px 纹理、均匀的 1px 自动描边、平铺的明度层级、弱剪影，是程序化产线的指纹。离商业发行级的差距不是加 20% 润色，而是大约 5–10 倍的“美术判断 + 返工迭代”。

> **重要说明：** `preview_scene.png` 不是“纯 tile 直接拼装”。除了 tileset，脚本还在场景层加了 5 块大污渍、2 条长裂缝、墙脚接触阴影和两团 dither 灯光。它们显著改善了观感；如果只看 tileset 直接铺出来的效果，会更平、更重复。这个差别本身就是探针结论的一部分。

## 1. 看起来像人画的，还是程序生成的塑料感？

**短答：远看像一套有纪律的暗色工业像素素材；放大看是“程序员画的像素画”。** 它不是那种高光乱飞、颜色脏、结构融化的 AI 塑料感，而是另一种问题：干净、平、重复、每个物件都像一个图标，而不是空间里的物体。

具体差在：

### 明度层次

- 当前地面基本是 1 个中间灰 + 极少深灰/浅灰点，墙面是 1 个深灰 + 顶部高光 + 底部阴影。整张场景的明度结构是“墙暗、地中、角色橙”，很简单。
- 手绘像素画会在每个材质里做更明确的**三段明度**和**焦点控制**：例如墙脚、门框内侧、地面被灯照到的区域，会主动拉开 2–3 个层次，而不是靠场景层临时撒 dither。现在的地面和墙在画面里几乎一样平，角色靠颜色而不是靠光值跳出来。
- 灯光只是把地面像素按圆形概率换成更亮的灰；它没有和灯具、遮挡、墙脚产生一致的关系。灯下的地面亮，但墙面、门框、角色没有对应的受光变化，所以“光”看起来像一层纹理，而不是空间里的光。

### 轮廓

- 角色使用统一的 1px 深色自动描边。这个方法在 16px 下保证了可读性，但每一条边都一样重，结果是“贴纸感”：头部、手臂、腿之间缺少手绘时会做的**选择性断边**和**内部深色结构线**。
- 角色的剪影是“头 + 橙色方块躯干 + 两根短腿”，没有肩线、没有衣物褶皱、没有重心。脸是白色椭圆上两颗黑点，像面具；左右侧面主要靠一个鼻子像素和单眼来区分。
- tile 的剪影基本都是矩形：墙、门框、读卡器、通风口都像从网格里抠出来的盒子。手绘会通过缺角、斜切、外露螺栓、边缘破损来打破 16×16 的矩形感；目前只有墙转角做了斜切。

### 细节密度

- 第一版地面/墙面每格撒了十几组噪点，拼起来像电视雪花；压干净之后，拼出来的房间又变得很空。**程序化纹理很难找到“手绘的中间值”**：手绘会在视觉焦点附近加密细节、在大面积地面留白，而代码生成的纹理要么均匀铺满，要么完全空白。
- 细节集中在几个小图标上（读卡器、通风口、格栅、血迹），大面积地面几乎没有信息。结果是“道具像贴纸，房间像测试场”。
- 16px 的重复周期在 20×12 房间里非常明显。最后场景只用了最干净的 `floor_concrete_c`，把变化交给大尺度 decal 和灯光——这等于承认 tile 本身的细节密度不适合大面积重复。

### 色彩

- 16 色调色板本身是这套产线最成功的部分：冷灰混凝土 + 橙色囚服/警示 + 暗红血迹 + 一点绿色 LED，整体是统一的，没有明显脏色。
- 但强调色层级偏弱：橙色囚服、橙色警示条、橙色灯管、橙色高光全在同一色相家族里，角色和场景装饰会互相抢。商业像素画会更严格地控制“谁最亮、谁最饱和、谁只出现一次”。
- 血只有暗红/红两个值，没有干湿、厚度、喷溅方向的变化；能读成血，但没有叙事。

### 一句话

**这套东西的“人味”主要来自调色板和限制，而不是造型能力。** 手绘像素画的核心是每个像素都在做形状/明度/材质的判断；这里很多像素是在执行规则（描边、平铺、dither、随机点缀）。远看能骗过眼睛，放到 4x 场景里就会露馅。

## 2. 哪些类别可以接受，哪些明显不行？

“可以接受”在这里指**原型/vertical slice 占位可用**，不等于商业最终质量。

| 类别 | 4x 可读性 | 判断 | 说明 |
|---|---|---|---|
| 混凝土地面 A/B/C | 高 | **可接受（占位）** | 平静、干净；但单 tile 变化太少，大面积会重复 |
| 排水格栅 | 高 | **可接受** | 格栅结构清楚，是这套里比较像“物件”的 tile |
| 墙面/墙转角 | 中 | **勉强可接受** | 墙段太平；转角斜切是少数有造型意识的处理 |
| 门框 | 高 | **可接受（占位）** | 能读出开口和门槛；但缺少门体、门缝、开合状态 |
| 钥匙卡读卡器 | 中高 | **可接受（图标级）** | 屏幕/键盘/LED 都能读；更像 UI 图标而不是墙上的设备 |
| 通风口 / 管道 | 中高 | **可接受（图标级）** | 能读；缺少和墙体的厚度、阴影关系 |
| 天花板灯座 | 中 | **勉强可接受** | 灯具本体能读，但“在头顶”这件事主要靠场景 dither 光池来解释 |
| 血迹 / 杂物 / 警示条 | 高 | **勉强可接受** | 第一眼能读，第二眼就发现是通用图形；没有叙事方向 |
| 4 方向角色（静态） | 中 | **明显不行（商业标准）** | 朝向能猜，但剪影、脸、四肢结构都像占位小人 |
| 2 帧行走 | 低–中 | **明显不行** | 只有手脚 1px 位移和一只脚抬起；没有重心、跨步、衣物/装备摆动 |
| 光照/场景 | 低 | **明显不行** | 场景层 dither 光池 + 接触阴影，不是可复用的光照系统 |
| 调色板/校验/工具链 | 高 | **强项** | 固定 16 色、逐像素校验、确定性重跑、4x 对照图，这些是真实生产力 |

**结论：** 地面、墙面、格栅、门框、读卡器、通风口、管道这些“材料 + 图标”类别可以进入原型；角色动画和光照不要自欺欺人，它们只是占位。血迹/杂物/警示条能撑气氛，但不能作为卖点。

## 3. 时间、代码量、换主题的边际成本

### 本次实测

- 从空目录到最终可运行版本：**约 12–15 分钟的 wall-clock**（本次会话；包含 5 轮目视检查和返工）。
- 脚本：**1027 行，895 行非空**（含注释、空行、场景合成和校验逻辑）。
- 纯生成时间：**约 1.1 秒**。
- 产物：14 个 tile、8 个角色帧、16 色 palette、1712×510 对照图、1280×768 场景。
- 主要时间不是写代码，而是**看图之后改图**：地面噪点太多 → 压干净 → 太空 → 加大尺度污渍；角色太矮 → 改比例 → 还是像方块人。这个“看—改”循环就是程序化产线真正的成本。

**注意：** 这是 AI 代理的 wall-clock，不是人类美术工时。一个熟练像素美术从零做同等内容，合理估计是 **1–2 天**（tiles + 基础角色），要做到商业级还要更久。不要拿 15 分钟去和人类几天的工期直接比较质量。

### 复用成本

这套脚本的可复用部分大约是：

- 16 色 palette 定义与逐像素校验；
- 像素绘制 primitive（rect / line / poly / hline / vline）；
- 自动描边；
- 4x nearest upscale；
- 默认字体阈值化 + 对照图排版；
- 20×12 场景合成、墙体旋转、房间接触阴影、dither 光池；
- 独立 tile / sprite 导出。

主题相关的部分主要是：

- 14 个 tile builder（地面、墙、门、设备、污渍）；
- 角色的身体比例、服装、脸、步态；
- 场景布局、灯光位置、decal 位置。

| 新任务 | 估算边际成本（同一代理、同一画风） | 说明 |
|---|---|---|
| 加 1 个 tile 变体/小道具 | 10–30 行，几分钟 | 复制 builder 改像素；校验和对照图自动复用 |
| 同一画风的 SCP 收容室/办公区，12–15 个 tile | 2–4 小时 | 仍需重新设计轮廓、材质、道具组合；不是“一键换主题” |
| 新调色板 + 新材质族 + 新房间 | 0.5–1 天（首版）；2–4 天（能看） | 颜色和明度关系要重做，不能只换 hex |
| 4 方向角色，商业级 6–8 帧行走 | 2–5 天或更多 | 这套 2 帧骨架可复用，但剪影、服装、重心、动画曲线要人做判断 |
| 100+ tile 的商业 tileset | 几周 | 需要数据驱动定义、图集管理、seam/engine QA；1000 行硬编码不可维护 |

**关键判断：** 这套“程序化”不是生成模型，而是**手写规则 + 手工调像素 mask**。换主题不是输入一句 prompt，而是重写 builder、重新做视觉判断。它的优势是“改一个参数能快速出 20 张变体、自动校验调色板、自动排对照图”，不是“自动产生好美术”。

## 4. 离商业发行级还有多远？缺什么？

**当前定位：原型/vertical slice 占位素材。** 不是可发行资产。

如果按 5 分制粗略打分：

- 材料/环境 tile：**2.5–3 / 5**（能读、能拼，但平、重复）
- 设备/图标类 props：**2.5–3 / 5**（可读，但通用）
- 角色静态：**1.5 / 5**
- 角色动画：**1.5 / 5**
- 光照/氛围：**1 / 5**
- 工具链/调色板纪律：**4.5 / 5**

综合大概是商业基线 **25–35%** 的水平；差距不是“再修一下边”，而是 **5–10 倍的迭代量**。缺的东西按优先级：

1. **美术方向（Art Direction）**
   - 统一的剪影语言：这套东西里哪些形状属于 SCP？门、灯具、角色应该有什么共同的形态特征？
   - 明度结构：主光、补光、暗部、焦点；现在只有“顶边高光 + 底部阴影”这一条规则。
   - 强调色策略：橙色只给角色？还是也给警示条？目前是混着的。
   - 参考图、mood board、风格规范：没有这些，代码只能产出“正确的通用像素”。

2. **英雄资产的造型与动画**
   - 角色需要重新设计：头身比、肩线、装备、身份识别（D 级人员不能只是一个橙色方块人）。
   - 行走至少 4–6 帧，最好 8 帧；要有 contact / down / passing / up 的节奏、手臂对摆、重心上下、脚掌滚动。
   - 待机、转身、受击、死亡、开门/刷卡等状态；这套脚本只有 2 帧。
   - 装备/血迹/服装破损等 overlay 系统。

3. **光照与后期**
   - 不是在地面上撒 dither，而是先定义光源、遮挡、反弹光，再把明度画进 tile 和角色。
   - 需要可复用的光照层、法线/自发光（如果引擎支持）、阴影形状，而不是每个场景单独写光池。
   - 当前场景的灯、光池、角色之间没有物理关系，这是“看起来像测试场”的主要原因。

4. **内容规模与工具链**
   - 14 个 tile 用 1027 行硬编码还撑得住；100+ tile 就需要数据驱动（tile 定义表、图层、palette 索引、动画帧表）和一个可视化编辑器/预览器。
   - 需要自动做 seamless tiling 检查、1x 可读性检查、引擎内 pivot/碰撞对齐检查。
   - 当前脚本能自动校验调色板，这是很好的基础，但它不能替代“美术总监看一眼说这不好看”。

5. **反馈闭环**
   - 商业像素美术是反复看、反复改出来的。这个探针已经证明：第一版能跑通，但第一版不能看；真正的时间在后面的 5 次返工。
   - 如果没有人类美术反馈，代理很容易在“技术上正确、审美上平庸”的解里收敛。

## 5. 最终判断与建议

### 这条产线适合做什么

- 快速做 **blockout / 占位素材 / 风格探针**；
- 批量出 **材质变体、图标、decal、警示标识**；
- 自动生成 **contact sheet、调色板校验、4x 预览**；
- 给美术做“第一版可编辑的底稿”，而不是最终稿；
- 在 jam/原型阶段，用极低工时把场景先跑起来。

### 不适合做什么

- 商业发行的 **hero character / 角色动画**；
- 需要强辨识度的 **SCP 视觉语言**；
- 需要真实光照和氛围的 **最终场景**；
- 大规模、长期维护的商业 tileset（当前代码结构会变成负担）。

### 建议的下一步（如果继续）

1. 保留 `gen_tiles.py` 作为 **material/variant/validation 工具**，不要把它当角色生成器。
2. 角色单独走一条线：先做 4–6 个手绘/精修的 4 方向关键帧，再用脚本做调色板替换和导出。
3. 把 tile builder 数据化（tile 定义表 + 图层 + palette 索引），否则每加一个主题都会复制粘贴。
4. 场景层不要用“万能 dither 光池”掩盖问题；先定主光和暗部，再决定要不要灯。
5. 如果目标是商业级，给美术留出 **至少 5–10 倍于当前探针的迭代时间**，并接受“程序化只负责底稿，不负责最终审美”。

**一句话总结：** 这条产线已经能稳定产出“能看、能拼、能校验”的暗色工业原型素材；但它产出的是 **developer art with a good palette**，不是商业像素美术。把它放在正确的位置（blockout / variants / tooling），它很有价值；把它当最终美术，会失望。
